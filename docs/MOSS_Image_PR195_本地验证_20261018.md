## 需要反馈的问题

### 1. Windows 中文路径的文本环境编码

关闭 Python UTF-8 模式，设置子进程输出 UTF-8，路径包含中文时，`te_env._side_site_dir()` 默认按 GBK 读取结果，稳定出现 `UnicodeDecodeError`，随后 `None.strip()` 失败。

最小修正为显式指定子进程 `PYTHONIOENCODING=utf-8`，以及父进程读取 `encoding=utf-8`。原始复现失败、修正版复验通过。完整 GPU 测试保持 PR 源码不变，通过 `PYTHONUTF8=1` 启动绕过。

证据：`windows_encoding_before.log`、`windows_encoding_after.log`；补丁：`te_env_windows_utf8.diff`。

### 2. 官方 ComfyUI 插件与 BF16 单文件的 QKV 布局

固定版本插件需要独立 `proj.q/k/v.weight`，Comfy-Org 文件保存 `proj.qkv.weight`。原始加载会漏载 Q/K/V，并遗留 fused QKV；LoRA 键名本身可以匹配。

在独立插件副本拆分密集 QKV，并生成配置对应的 RoPE buffer 后，小型模型与完整模型加载均通过。小型 BF16 对照误差约为底模 0.20%、LoRA 后 0.26%。**本补丁未覆盖 INT8 ConvRot 文件。**

证据：`comfy_load_probe_before.json`、`comfy_load_probe.json`、`comfy_real_result.json`；补丁：`comfy_dense_qkv_adapter.diff`。

### 3. Auto 缺少 MOSS 显存表

`FamilyDescription.train_memory` 为空。实测规划器在约 5.5GB 可用、0.25MP 条件下返回 INT8、0 块交换，并说明没有该家族的显存数字。因此本轮使用明确交换块数，不能把 Auto 当作已验证的 8GB 预设。
