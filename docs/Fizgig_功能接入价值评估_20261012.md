# Fizgig 功能接入价值评估

调查日期：2026-10-12。仅评估接入方案，未修改功能、升级引擎、运行 GPU 推理或发布版本。

## 核对范围

- 本工具固定 Fizgig **v7.0.1**，commit `1c8ec88edc1a4f99f73585aeae00fec740b12ea6`，见 `kohya_core/fizgig_engine.py:19`。
- 上游当前 HEAD 为 `c692119cbd61c9b59ca762b88bfa8ce9323171a9`；远端存在 v7.3.0 标签（提交 `db917987c8289484eac9f7d30cf8b9b58940acf7`）。当前 README 已包含 ACE-Step 音乐功能。本次截图里的五项主要工作台功能在 v7.0.1 已存在，不需要为这些功能一并引入音乐模型。
- 读取上游 README、CLI、TRAINING、FINETUNE，以及本工具固定版本的工作台源码。源码档案读取不等于功能运行验证。

## 现有接入

`kohya_core/fizgig_adapter.py:269` 固定 `--network_type lora`；已传递精度、块交换、EMA 0.98、可选自适应学习率、状态保存/续训以及训练采样参数。没有开放 LoKR、全模型微调、Context LoRA 和上述工作台。

本工具已经有概念滑块 LoRA 训练；Repair Studio 修改的是已训练 LoRA 的分层权重，两者不共用同一个用户概念。

## 优先级建议

以下是结合现有产品的工程判断，不是上游对训练质量的保证。

| 功能 | 用户价值 | 推荐阶段 | 接入方式与限制 |
| --- | --- | --- | --- |
| 训练结果对比 / Royale | 固定条件比较不同检查点，选择合适轮次，导出对比图 | 第一阶段 | 优先复用已有采样结果；缺少采样时再按需生成。提示词、种子、底模和采样参数必须一致。首版不需要 MP4/GIF。 |
| LoRA 分层调整 / Repair | 保留人物特征，同时尝试减弱衣服、背景、画风牵连 | 第一阶段 | 选择本地 LoRA，调整层组，固定种子预览，另存新文件。先做单 LoRA，不做 donor 混合。不能保证修复训练失败、多人串特征或缺失的能力。 |
| 自动显存规划与预览失败恢复 | 减少新手参数选择和因采样中断训练的问题 | 持续优先完善 | 现有接入已有部分 auto 参数；检查上游 planner 的真实生效值和各模型差异，展示实际选择的精度/交换方案。不能把某模型 8GB 配方推广到全部模型。 |
| LoRA 压缩 / Extract | 减小成品文件、方便分享和管理 | 第一阶段末 | 先支持普通 LoRA；用权重 SVD 降 Rank，不需要底模。压缩后应对照验证，不能保证无损。LoKR/LoHa 的稠密分解更重，不与普通 LoRA 承诺相同速度和内存。 |
| 分层分析 / Profiler | 给分层调整提供依据 | 第二阶段 | 区分不加载底模的权重/Rank 分析与需要 GPU 生成的消融分析；语义结论依赖提示词、种子和参考图。人脸相似分数仅辅助，不作为二次元、多角色、画风模型的自动质量判断。 |
| LoKR | 为进阶用户增加训练网络选择 | 第二阶段 | 上游 trainer 有 `--network_type lokr --lokr_factor`；本工具目前固定普通 LoRA。需要独立参数、导出格式及 ComfyUI 兼容验证；不能宣传普遍优于 LoRA。 |
| Context LoRA | 在已有人物/画风 LoRA 上训练新衣服、人物或属性 | 第二阶段可选 | 旧 LoRA 冻结并在训练中启用；使用结果时通常需要一起加载旧、新 LoRA，保持上下文强度。增加依赖管理，不是自动多人解耦。 |
| 变体探索 / Explorer | 快速尝试已有 LoRA 的不同表现 | 后续实验功能 | 随机扰动已存在的分层权重，人选择变体，多轮预览有推理成本；不会凭空学到新能力，也不保证质量递增。 |
| 全模型微调、底模差分提取 LoRA | 给高需求用户提供另一条训练路线 | 暂缓 | 依用户此前决定先完善 LoRA。涉及底模来源、完整状态、RAM/磁盘预算及额外训练验证。普通 LoRA 降 Rank 与“微调底模减原底模再提取 LoRA”是不同功能。上游的质量对比属于其特定实验。 |

## 首版产品入口

建议增加一个“LoRA 工作台”，从训练结果页和本地 LoRA 文件进入，先包含：

1. 对比：固定条件查看不同检查点与 LoRA 权重。
2. 调整：层组权重与原版对照，另存成品。
3. 压缩：显示原/目标 Rank、文件大小和对照入口。

高级参数折叠；只显示当前模型支持的工具。不同引擎的 LoRA 可以按兼容格式导入，但仍需匹配模型架构与底模，不承诺所有 safetensors 都通用。

建议顺序：结果对比 → 分层调整 → 普通 LoRA 压缩 → 分层分析/LoKR。显存规划与下载、采样可靠性贯穿上述阶段。
