# LoRA 工作台 / LoRA Studio：当前实现与后续方向

## 当前范围：Krea 2 / Anima

入口：新版界面左侧 **LoRA 工作台**。依赖已准备好的 Fizgig v7.0.1；不会切换训练项目的引擎版本。缺少环境时，可从工作台打开 Fizgig 的准备入口。

### 界面流程（2026-10-13 重做）

主流程：**选择 LoRA → 配置分析 → 调整效果 → 对照与导出**。

- 选择文件后自动读取架构；当前项目的训练检查点也可直接选用。
- 底模、文本编码器、VAE 和验证提示词提前到分析配置页；采样参数与扩展分析折叠。读取已有模型配置只更新模型路径，保留明确选择的精度和采样参数。
- 配置页显示实际预计生成张数；可跳过 GPU 分析，直接手动调整并导出。
- 调整页仅保留一份分组导航，右侧显示所选组的原版 / 单独保留 / 关闭对照。本组倍率固定在右侧底部，图片与高级逐层设置独立滚动。
- 官方建议与命名预设放入侧栏；预设保存、应用、删除及撤销继续使用已有接口。
- 对照与导出独立成页；倍率或采样参数变化会标记旧图片，倍率变化后旧导出记录也会标记为上次导出。权重压缩的输出不会当成调整版导出结果。
- 页脚主按钮按步骤切换，缺少必需配置时显示原因；任务进行中显示进度与停止入口。压缩作为独立工具入口。

### P1：权重编辑

- 选择 `.safetensors` LoRA 或当前项目的训练检查点，读取实际模型层级。
- 单层倍率、整组批量设置、关闭 / 恢复、全部重置、另存新文件。
- 使用 Fizgig `families.lorafile.lora_pairs` 和官方模型驱动进行架构 / 层级映射。
- CPU 权重分析直接调用 `families.block_profile.weight_stats`，显示各层原始权重的相对规模；**这不是视觉贡献或画质评分**。
- 权重修改调用官方 Repair 的 `_bake_single_contribution`，本工具只负责映射与文件序列化，不复制缩放算法。
- v7.0.1 的完整 `save_repaired_lora` 使用旧式层名匹配，不能完整覆盖 Krea 的 I/O 与 Anima 命名，因此没有直接套用该入口。适配器明确绑定 v7.0.1，后续升级需再次核对接口。
- 保留原始文件键名格式。官方处理吸收原始 alpha / rank 后，对相应输出 alpha 设为 rank，维持预期有效强度。
- 原始文件 SHA256 防止操作期间被替换；导出先写临时文件，完整后原子保存，禁止覆盖源文件及其硬链接。

### P2：内置预览

- 使用 Fizgig `FamilyDescription.make_workbench_engine()`、`ensure_pipeline()`、`generate_preview()`。
- 原图加载原始 LoRA；调整图加载 **同一官方 Repair 处理入口生成的临时 LoRA**，两边均使用默认层级倍率。
- 固定同一个底模、提示词、种子、尺寸、采样步数、CFG 和使用强度。支持图片放大；修改参数后旧图会标为上次结果。
- 预览的整体 LoRA 使用强度不会写入导出文件。
- 预览结束清理临时 LoRA，保留图片与参数报告。拖动滑块不自动出图；点击“生成对照”才加载模型。
- 不依赖 ComfyUI。需要 CUDA / ROCm，需选择匹配的底模、VAE、文本编码器。Anima 支持标准 28 层架构。
- 模型精度显式选择不受支持时报告错误；核对所有 LoRA 模块是否完整加载，避免产生误导性对照。

### Profiler 快速分组分析（2026-10-13 接入）

- 使用官方 `block_profile.windows`、`conditions`、`run_ablation`、`verdicts`、`repair_settings`；不复制图片差异计算或建议判定算法。
- 分析对象为原始 LoRA，当前手工分层倍率不参与测量。固定一个种子，对照原版、停用 LoRA、各组单独保留、各组关闭；配置分析页显示预计生成张数。
- 可选填写不含角色触发词的场景提示词。启用后追加该场景的同组对照，生成张数加倍。
- 保存全尺寸 PNG 和官方缩略图，在界面内选择分组查看、点击放大。显示分组的画面变化量与官方建议；变化量不是画质分数。
- Krea 2 可选 1–3 张真实人物参考照片，复用官方 ArcFace 接口。需现有 Fizgig 环境包含分析依赖、用户目录已有 buffalo_l 检测与识别模型；未安装时明确提示，本任务不自动安装或下载。参考照片未检出人脸时阻止启动 GPU 分析。
- Anima 暂不提供人脸相似度分数，只展示画面变化及对照。没有人脸评分时不判断角色相似度或特征泄漏。
- “应用建议”将当前分层倍率替换为官方建议，支持撤销。影响较小的分组建议尝试关闭，泄漏高于相似度贡献的分组建议减弱至 0.5；其余保持 1。结论仅针对本次采样条件，应用后需生成原版 / 调整版对照确认。
- 分组快捷按钮提供 0.85、0.7、关闭和恢复。逐层滑块默认折叠为高级设置；每层旁显示所属分析组的结论。
- 改变提示词、模型路径、种子、采样设置或参考照片后，标记旧结果并禁用旧建议应用。调整层级倍率不使原始 LoRA 的分析过期。
- 与 A/B 预览复用同一模型加载和模块完整性检查。分析期间模型常驻于该任务进程，结束释放；不同任务仍各自加载模型。
- 进度按生成张数及当前采样步数显示，可停止。成功结果记入 `last_profile_task`，同一 LoRA 在后续生成 A/B 后仍可恢复此前分析。

### 调整预设

- 命名保存当前所有层级倍率、加载、删除、撤销应用；不修改源 LoRA。
- 存储：用户数据目录 `settings/lora_workbench_presets.json`，最多 100 个。
- 记录模型家族、实际 Block ID、来源 LoRA 指纹和内核版本。模型家族或层级结构不匹配时禁止套用；同结构的其他 LoRA 可应用，但明确标记需要重新出图确认。
- 不提供未经验证的“保脸 / 去画风”通用语义预设。

### 已有附加功能

CPU 权重压缩调用 Fizgig 的 `extract.reduce_pair`，降低原文件 Rank 后另存；当前分层设置不参与压缩。压缩保留的权重能量比例不代表画质，需出图确认。

### 文件与任务

- 普通二维线性 LoRA；LoKR、LoHa、DoRA、卷积 / 融合变体暂不支持。
- 未映射权重和附加张量在调整版中原样保留，并明确提示；这类文件不提供完整预览或压缩。
- 与训练 / 下载共用任务锁；进度、失败原因、停止按钮和重新打开后的任务恢复。
- 状态：用户数据目录 `settings/lora_workbench.json`。
- 报告 / 预览：`cache/lora_workbench/<任务 ID>`，不写入发布素材。
- 工作进程使用 `python -I`，避免项目内 `queue.py` 等文件影响依赖。
- 打包清单包含独立 worker。

## Anima 社区分组与一键对照（2026-10-18）

- 标准 Anima 28 层 LoRA 统一使用七个社区分组，取消“分析分组 / 社区经验分组”切换：细节与结构 L00–L03、体型与姿态 L04–L08、构图与脸型 L09–L13、眼区与表情 L14–L17、鼻口与下半脸 L18–L21、材质与光影 L22–L24、画风与色彩 L25–L27。名称依据 Crody 的合并观察归纳，各层影响可能交叠，不预填语义倍率。
- 配置底模与验证提示词后，点击“生成分组对照”即可一次生成原版、停用 LoRA、每组单独保留及每组关闭的结果。完整 28 层、无其他组件时共 16 张；启用无触发词场景后为 32 张。稀疏文件只比较实际包含的分组，其他组件单独比较，界面显示实际预计张数。
- 选中任意分组显示原版 / 仅保留本组 / 关闭本组三图，可切换单张大图，也可采用某张图的完整条件继续变体探索。分组测量使用原始 LoRA；修改倍率后使用原版 / 调整版 A/B 确认。
- 复用官方 Profiler 的条件生成、采样、图片差异与建议算法，仅在当前任务的引擎实例上提供社区分组；任务结束恢复原分组。Krea 2 保留其原生分组。
- 新旧结果按分组 ID 和实际 Block ID 核对。旧 Anima 分组结果保留在缓存，界面提示重新生成；不将旧分组的图片、指标或建议套入新社区分组。手工倍率、冻结状态和预设仍按实际 Block ID 保存。
- 标题栏“层级参考”提供 L00–L27 的简要观察、原作者来源和核对日期。“调整此组”定位分组并展开逐层控件；各层旁显示社区观察。该资料不能当作各层固定职责或训练层选择配方。
- 检查报告记录 `architecture_blocks` 与 `profile_grouping`。标准 28 层映射下，稀疏 LoRA 不补建缺失层；旧记录缺少架构字段时，只有完整 L00–L27 映射启用社区分组，否则重新读取后再判断。Krea 2 或非标准 28 层映射不套用此参考。
- 前端与独立 worker 共用 `kohya_core/anima_layer_guide.json`，安装包清单包含该文件，确保分组名称、范围与实际采样条件一致。

来源及证据边界见 [Anima 28 层研究](Anima_28层结构与社区分层研究_20261018.md)。

### 大画布与官方 Explorer 接入（2026-10-13）

- 工作台占用可用窗口，标题、文件信息与导航改为紧凑布局。
- 分层编辑采用左侧分组、中间图片、右侧参数的三栏结构。图片区域按剩余高度伸展，完整显示图片；倍率、统计和高级设置仅在右侧面板滚动。参数栏可收起。
- 分组对照可切换三图并排或单张大图。优先读取完整 PNG，尚未加载时显示缩略图，点击仍可打开原图。
- 新增“变体探索”，直接调用固定 Fizgig v7.0.1 的 `SliderState.mutate`，不复制变体生成算法。
- 每轮使用当前倍率作为基准，生成 1 张基准图与 4 张变体，保持底模、提示词、采样种子、尺寸、采样参数和整体 LoRA 使用强度一致。
- 按官方四候选调度：前两个使用配置的结构性变化，第三个为随机变化，第四个在剩余可调整层至少 2 个时避开上次选中的变化层。结构性变化受官方强度阈值控制，界面说明该条件。
- 可以冻结分组或单层，保留当前倍率。变化幅度、结构性变化、变化层数、变体随机种子可配置；所有层冻结时阻止生成。
- 选中候选后回写全部层级倍率；保留官方层的开关状态和隐藏倍率，确保后续迭代仍能使用官方的开关变异机制。下一轮由用户点击启动，不自动增加 GPU 任务。
- “继续探索”只更换变体随机种子，采样种子保持不变；高级入口可按指定变体种子生成。按模型实际 Block 顺序构造状态，避免不同进程的集合顺序影响可重复性。
- 已选方案可转入分层调整、生成原版 / 调整版对照、保存预设或另存 LoRA。撤销保留上一次倍率操作；尚未提供完整多轮历史浏览。
- 变体预览使用与导出一致的官方 Repair 权重处理入口；每轮加载一次预览引擎，结束释放。没有跨任务的模型常驻缓存。
- 倍率范围与官方变异范围对齐为 −3 至 +3。改变采样条件或修改成不属于本轮的倍率后，旧候选标记过期并禁止继续套用。新增冻结设置会阻止选择改变该冻结层的旧候选。
- 记录保存至已有工作台设置与缓存目录，可恢复最近一轮结果。源 LoRA 不被覆盖；任务结束或取消后清理探索用临时 LoRA。
- Explorer 只提供候选，不按 loss、图像差异或权重规模自动认定画质改善。当前仍仅支持 Krea 2、Anima 的普通线性 LoRA。

### Explorer 参数含义澄清（2026-10-13）

“构图变化”更名为“层级结构扰动”，“变化幅度”更名为“权重扰动幅度”。百分比描述官方权重扰动参数，不是生成图片的变化程度。结构性扰动只作用于前两个候选所选层中的第一层；其他层采用普通随机扰动，倍率仍受 −3 至 +3 范围限制。

Anima 当前以第 0 层作为该算法的扰动入口，并未验证其具有专门的构图控制语义。固定提示词与采样种子用于比较 LoRA 权重变化，不能据此保证新姿势、镜头或场景。若要检查对不同构图的适应性，应由用户另选提示词或采样种子，并在新的条件下重新生成基准与候选。不得静默替换提示词或种子来夸大权重调整的效果。

### 分析图设为探索基准（2026-10-13）

- “原版 LoRA／仅保留本组／关闭本组”图下新增“以此为基准探索”。采用图片实际对应的全套层级配置，不使用当时右侧滑块的临时数值。
- 原版将所有映射层恢复为 1；仅保留本组将该组设为 1、其他组设为 0；关闭本组将该组设为 0、其他组恢复为 1。保留原始 LoRA 文件。
- 新 Profiler 报告直接记录官方 `conditions` 所定义的每张图对应的全量倍率；已有报告根据完整模型层级与明确的 keep/drop 分组条件兼容恢复，无需重新运行分析。
