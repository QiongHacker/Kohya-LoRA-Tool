# Qwen-Image-2.1 分片权重加载兼容诊断（2026-10-13）

## 反馈证据

- 反馈包：KohyaLoRA_训练反馈_20261013_133317_801045_6fe22775.zip。
- AI Toolkit / qwen_image_2，默认下载的 Qwen/Qwen-Image-2.1 完整 Diffusers 目录。
- 40 张图片，rank/alpha 32，2000 步，qfloat8；报告显示 NVIDIA、约 44.47 GiB 显存。
- 两个 transformer 权重分片加载后，在第一个 FFN 块迁移设备时失败；尚未进入训练迭代。
- 直接异常：Cannot copy out of meta tensor; no data!
- 反馈包不含实际权重、完整硬件/依赖诊断，不能据此证明大模型 GPU 训练通过。

## 根因和复现

官方 Diffusers checkpoint 使用每层 img_mlp.gate_layer.weight / img_mlp.proj.weight。
新版 AI Toolkit 模型改用 fused img_mlp.gate_up.weight。单文件有转换函数，目录加载路径未调用它。
使用同一模型类的小型单层配置、官方拆分命名格式，在 CPU 重现该异常：未加载参数为
transformer_blocks.0.img_mlp.gate_up.weight，移动模块时抛出相同 NotImplementedError。

## 修复

仅为 Qwen-Image-2.1 的目录加载入口添加兼容处理：按原 checkpoint 读取 gate、up，
按 gate 在前、up 在后的顺序逐层拼接并赋值。检查其他 missing / unexpected / mismatched
和全部 meta 参数、buffer；失败明确报错，不分配未初始化权重。
原权重文件不重写；引擎源码补丁自动备份、重复应用保持同一入口。
主程序启动/更新入口和 PyInstaller runtime helper 资源已接入。

## 已完成验证范围

- 原始 CPU 加载复现：存在 meta FFN，模块迁移失败。
- 隔离引擎源码应用补丁两次，静态入口检查通过。
- 小型双分片目录经过实际 load_model API：meta 参数为 0，CPU 模块迁移通过。
- 所有加载后的 tensor 数值与转换前参考值逐项 torch.equal 为 True。
- 完整 32 层 meta 架构与官方索引：297 个原始名称转换为 265 个目标名称，缺失/多余均为 0。
- Python / PowerShell 语法检查、git diff --check 通过。
- 未加载用户的完整大模型；未执行 FP8 GPU 量化、训练迭代或质量评估；未构建或发布新版本。
